About the Project

MediEvidence: Complete Project Architecture

A domain-specific AI assistant built for evidence-grounded research discovery in digital healthcare.

🔬

What is MediEvidence?

MediEvidence is a Retrieval-Augmented Generation (RAG) system that enables researchers to ask natural-language questions about a curated corpus of 30 peer-reviewed digital healthcare research papers and receive evidence-grounded answers with exact page-level citations.

🎯

Problem Statement

Researchers frequently remember a concept, finding, or statistic from a paper but forget which paper contains it. Manually searching through 30+ PDFs is time-consuming. MediEvidence addresses this through semantic retrieval, hybrid search, and citation synthesis.

✅

Core Objectives

  • Semantic natural-language question answering
  • Dual-path dense + sparse retrieval
  • Cross-encoder neural reranking
  • Page-level evidence citations
  • Zero-hallucination out-of-domain refusal
  • 100% source-traceable answers
Complete RAG Pipeline

End-to-End Architecture — 9 Stages

01

Research Paper Collection

30 PDFs · 5 Categories · 2022–2026
✓ Implemented ▼
Input: Research queries and manual curation
Output: 30 open-access PDFs across 5 healthcare AI sub-domains
Details: Papers curated from arXiv, Frontiers in Digital Health, and peer-reviewed conferences covering Medical Imaging AI, Digital Health & RPM, Digital Twins, Healthcare IoT/Wearables, and Clinical Decision Support Systems. Each paper has a unique ID (e.g. MED-DT-001), DOI link, and license metadata.
02

PDF Extraction & OCR

PyMuPDF (fitz) · Selective Tesseract OCR
✓ Implemented ▼
Input: 30 PDF files
Output: 570 extracted page texts with page metadata
Details: PyMuPDF extracts digital text with 100% success rate (570/570 pages). Selective Tesseract OCR is configured as fallback for scanned pages (0 OCR pages in this corpus). Each extracted page preserves: paper_id, original_page index, section_heading (if detectable), char_count, word_count. Stored in data/extracted_text/.
03

Semantic Chunking

550-char chunks · 100-char overlap · Page-aware
✓ Implemented ▼
Input: 570 extracted page texts
Output: 570 research-aware text chunks with full metadata
Chunk size: 550 characters (target)
Chunk overlap: 100 characters
Unit: Characters (not tokens)
Avg chunks per paper: 19 chunks
Metadata per chunk: chunk_id, paper_id, paper_title, authors, doi, original_page, section_heading, char_count, word_count, text_content
Storage: data/metadata/chunk_metadata.csv
04

Dense Embedding Generation

all-MiniLM-L6-v2 · 384-dimensional vectors
✓ Implemented ▼
Model: sentence-transformers/all-MiniLM-L6-v2
Embedding dimensions: 384
Normalization: L2-normalized unit vectors for cosine similarity
Mode: Offline (HF_HUB_OFFLINE=1, cached weights)
Output: 570 dense vectors stored in Qdrant collection
05

Qdrant Vector Database

Qdrant Local Disk · HNSW · Collection: medievidence_papers
✓ Implemented ▼
Database: Qdrant v1.x (local embedded disk storage)
Collection: medievidence_papers
Index type: HNSW (Hierarchical Navigable Small World)
Similarity metric: Cosine
Indexed records: 570 chunks
Storage path: data/qdrant_storage/
Payload: Full chunk metadata stored alongside each vector
06

Hybrid Retrieval (Dense + BM25 → RRF)

Qdrant HNSW + BM25Okapi → Reciprocal Rank Fusion k=60
✓ Implemented ▼
Dense path: Query encoded with all-MiniLM-L6-v2 → Qdrant cosine ANN search → top-K candidates
Sparse path: BM25Okapi (k1=1.5, b=0.75) inverted index over all chunk tokens → lexical ranking
Fusion: Reciprocal Rank Fusion (RRF) with k=60 combines both ranked lists into a single unified ranking
Output: Top-12 fused candidates passed to reranker
07

Cross-Encoder Neural Reranking

ms-marco-MiniLM-L-6-v2 · Joint Attention Scoring
✓ Implemented ▼
Model: cross-encoder/ms-marco-MiniLM-L-6-v2
Input: (query, passage) pairs from top-12 RRF candidates
Mechanism: Joint cross-attention computes relevance score for each pair simultaneously, eliminating false-positive vector neighbors
Output: Top-K passages re-sorted by cross-encoder relevance score
08

Answer Synthesis & Guardrails

Evidence-grounded · Zero-hallucination · Page citations
✓ Implemented ▼
Method: Extractive synthesis from top-K reranked passages (no LLM hallucination)
Guardrail 1: Whole-word regex domain keyword boundary check
Guardrail 2: Calibrated cosine confidence threshold (default: 0.35)
Citation format: [Paper Title (Year), Page X]
Out-of-domain: 100% refusal — no fabricated answers
PICO evidence: Structured Population/Intervention/Comparison/Outcome breakdown
09

Evidence Verification & Citations

Paper ID · Page Number · DOI · Source Link
✓ Implemented ▼
Each citation contains: paper_id, full title, authors, year, doi, original_page index, source_url
Verification: User can open original PDF via DOI link and navigate to cited page
Traceability: Every chunk preserves its exact source page metadata throughout the pipeline

Rigorous Benchmarking

Evaluation & Groundedness Metrics

Evaluated on 50 comprehensive benchmark questions across 10 categories (42 clinical + 4 out-of-domain + 4 insufficient-evidence) with actual measured results.

📋 Evaluation Methodology

Recall@1
Target ground-truth paper is the #1 retrieved candidate across domain questions.
MRR (Mean Reciprocal Rank)
Average reciprocal position of the first relevant paper across all queries.
nDCG@5
Normalized Discounted Cumulative Gain measuring position-weighted retrieval quality in top-5.
Out-of-Domain Refusal
Percentage of non-medical queries correctly refused with no fabricated answer generated.
Citation Accuracy
Every generated assertion links directly to a verified paper_id and original_page metadata entry.
Sample Size
50 total questions: 42 clinical domain questions across 8 categories + 4 out-of-domain refusal tests + 4 insufficient-evidence boundary tests.
